▸ Dataset & how to extend this

Every data source lives in its own file, loaded via <script src> before the app logic, so each can grow (or be swapped) independently. Nothing is embedded in this HTML file:

  • diseases-data.js → DISEASES — subject → tier (common / lessCommon / rare) → disease names.
  • clinical-findings-data.js → CLINICAL_FINDINGS — body system → named signs/findings (browsable reference list).
  • concepts-symptoms.js → SYMPTOMS, concepts-signs.js → SIGNS, concepts-complications.js → COMPLICATIONS — concept pools, each id → label.
  • concepts-investigations.js → INVESTIGATIONS (routine/first-line workup) and ADVANCED_INVESTIGATIONS (tertiary/high-end-center-only tests — genetic panels, biopsy, advanced imaging, etc. Rendered as its own section below Complications on a disease's detail card).
  • concepts-basic-science.js → BASIC_SCIENCE — concept pool grouped by discipline: anatomy / physiology / biochemistry / pathology.
  • concepts-management.js → MANAGEMENT_CONCEPTS — concept pool grouped by modality: pharmacology / surgery / psychology / lifestyle.
  • disease-relations-data.js → DISEASE_RELATIONS — the relation map, diseases so far. Maps each disease name to the concept ids above (not the labels themselves) — this is the edge list a network graph is built from: each disease is a node, each concept id it references is a node, and each reference is an edge. Diseases with an entry show a green ● pill in the Diseases and Browse tabs — click/select one to open its full detail.

To add a new disease's profile: reuse existing concept ids wherever they already apply — that's what creates shared nodes/edges between diseases in the graph. Only add a brand-new "id": "Label" entry to the relevant concepts-*.js pool if the concept genuinely doesn't exist yet, then reference that new id from DISEASE_RELATIONS (use the new "advancedInvestigations" array for tertiary-only tests — it's optional, leave it [] if none apply). Never invent an id inline in the relation map without also adding it to its pool.

Concept Explorer (the "Concept Explorer" tab) is built generically from DISEASE_RELATIONS — it doesn't hardcode any disease or concept. A small CATEGORY_DEFS list in the script maps every field on a disease entry (symptoms, signs, investigations, advancedInvestigations, the four basic-science disciplines, the four management modalities, complications) to its concept pool. Picking any concept walks that map to find level 1 (every disease referencing it) and level 2 (every other concept those diseases in turn reference) — so adding a disease or concept to the files above automatically extends the explorer too, with nothing to update in the explorer's own code.
