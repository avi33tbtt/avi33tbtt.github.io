Nested Analysis View — Unified Cohort Trajectory Map

cohort_graph.json → one alluvial network of every patient's checkpoint sequence, T1D and T2D overlaid on shared nodes · inspired by the Evidence-Pyramid Trajectory Mapper's cross-case hub view · runs entirely in-browser, no Python/Node required
What this is. Steps 3–6 each show one lens on the cohort graph at a time (a toggle, an anchor, a filter, a summary). This page nests every patient's trajectory in whatever cohort_graph.json you load into a single network — the sample data ships with eighteen, but any cohort size works the same way: every patient walks the same six generic checkpoints (Diagnosis → Presentation → Initial plan → Escalation → Advanced/recurrent → Disposition), and where two or more patients land on the same checkpoint value, their lines are drawn through one shared node instead of parallel ones — exactly the convergence/divergence reading used in the case-report trajectory mapper this view borrows its shape from. Pick a patient below to see their own path highlighted against the rest of the cohort — "how your patient is moving" relative to everyone else on the same map. Synthetic data only, not clinical decision support.

What the convergence pattern shows

Confounder. This nested view reuses the same six generic checkpoint slots for every patient regardless of disease (per the Step 7 generalization audit) — but T1D's "Escalation" / "Advanced or recurrent" columns are almost always populated (irregular acute-spike events recur over years), while most T2D patients only have one or two outcome nodes on file, so those columns read heavily "—" for T2D. That's a real difference in this synthetic corpus's event density per disease, not a rendering gap — see Step 7, Issue 2 for the related, already-flagged exception in the comparator filter.
